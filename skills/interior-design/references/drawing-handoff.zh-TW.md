# 不熟工程圖，也能把想法說清楚

本專案的目標是**和設計師、工程師溝通**。以下是以台灣住宅裝修協作為背景的工作清單，不是法規條文、國家標準、契約範本或專業簽證。實際圖面、比例、責任與送審要求須由負責專業、業主及承攬廠商約定。

## 三種資料，各自解決不同問題

| 階段 | 問題 | 應提供的資料 | 本版 |
|---|---|---|---|
| 概念設計 | 我想要什麼感覺？ | 需求、參考圖、風格、色彩、草模、渲染 | 有引導流程；範例高清示意圖 |
| 設計協調 | 放哪裡、尺寸多少、哪裡還沒確認？ | 平面、牆面定位、門窗表、材質意向、待確認事項 | 有單房圖面與表格 |
| 施工與發包 | 用什麼構造、怎麼接、誰施工？ | 施工詳圖、各工種圖、規範、界面責任、核定材料與現場資料 | 尚未提供，不得據此施工 |

漂亮的圖是討論工具；高清像素不等於工程精度。JSON 尺寸正確也不等於現場正確。

本版立面稱「基準立面／datum elevation」：定位方向固定為南北牆由西到東、東西牆由南到北。這不是完整的室內向牆觀看投影，避免把未鏡射的基準視圖當成施工正立面。圖上已寫明此限制。

## 讀尺寸前先確認

- 單位：圖面與 JSON 是 **mm**，Blender 內部是 **m**。GLB 轉為 Y-up 座標。
- 房間寬深為完成面之間的內淨尺寸；牆厚向外建模，並不代表已確認構造。
- `x/y` 是家具左下界座標，不是中心。原點為房間西南內角。
- 高度基準 `FFL = 0` 是示意完成地坪；現場樓板、降板、門檻與地坪完成厚度未處理。
- PDF/SVG 為 A3、1:50，必須 100% 列印才能保有名義比例；「符合頁面」會改比例。**以標註尺寸為準，不量圖片。**
- 渲染圖與 3D 視窗都是透視或軸測，不可拿像素換算施工尺寸。
- `assumed` = 示意假設；`site_measured_unverified` = 有丈量但未覆核；`site_measured_reviewed` = 使用者記錄為已覆核。程式不會檢驗實際現場，也不因此變成施工核定。

## 通常仍需另外補齊的資料

依專案與工種需要，請負責專業評估：現況丈量、拆除／新作牆體、地坪鋪面、天花與照明、插座／弱電／迴路、給排水、空調／通風、廚衛防水、固定家具立面剖面、門窗及五金細節、材料規格與節點大樣、結構及消防介面。

本版**沒有**做這些設計，也沒有檢查法定通道寬、無障礙、用電容量或建管／消防申請需求。不用假數據填滿表格；應標「待確認」。

## 開會時可以直接問

1. 設計師：「我喜歡這個光線和材質，但配置是否符合我的使用方式？哪個尺寸最影響動線？」
2. 工程師／承攬廠商：「哪些尺寸需要重丈？這些門窗是名義尺寸，實際洞口與收邊要留多少？」
3. 各工種：「水電、空調、天花、木作在哪裡互相影響？要補哪一張剖面或節點才可估價？」
4. 共同確認：「哪些已決定，哪些只是意向，誰負責回覆？變更後要重出哪些圖？」

## 版本與交付

每次修改保留專案 JSON 和版本號，例如 P01、P02；重建整包，不只換一張漂亮圖。交付時附來源 JSON、圖面、材質／門窗表、問題清單、檔案 manifest。不要只傳聊天截圖。

收到對方的修改後更新唯一資料來源，重新檢視模型、圖面與尺寸。若對方只在 CAD 或 Blender 手改，必須把差異回填或清楚記錄，不能聲稱仍完全同步。

交付語句建議：

> 這是 P01 設計協調草圖，目的是確認風格、位置與名義尺寸。尺寸尚需現場覆核；水電、結構、防水及施工節點未包含。請協助列出需要補齊的資料，確認後再進入估價或施工圖階段。


Scale note / 比例補充：A101 深度超過 8000 mm 時改用 1:100；其餘為 1:50。請以各張圖框比例為準。平面表最多列前十件家具，完整清單在 furniture.csv。家具各邊至少 150 mm；示意家具不代表實品。
